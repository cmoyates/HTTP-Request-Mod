# Minecraft ↔ pi WebSocket protocol v1

This document is the normative wire contract between HTTP Request Mod and a separately maintained companion pi extension. The mod repository does not include the extension implementation; use [the companion build guide](building-pi-extension.md) to create it in its own repository.

## Transport and authentication

- The transport is one persistent RFC 6455 WebSocket.
- Each application message is one complete UTF-8 JSON text message containing one object.
- Every object has integer `version: 1` and a string `type`.
- Unknown object fields are ignored for forward-compatible additions. Unknown message types and unsupported versions are errors.
- Binary messages are unsupported.
- The maximum application message is 65,536 UTF-8 bytes. The Java client also bounds its decoded accumulator to 65,536 UTF-16 code units.
- A conforming companion extension must disable WebSocket compression.
- If configured, the mod sends `Authorization: Bearer <sharedToken>` in the HTTP upgrade. The token never appears in an application message or URL.
- The extension binds to loopback by default. Remote binding requires a shared token and TLS. The mod likewise requires `wss://` and a token for a non-loopback endpoint.

The token, authorization header, prompt and response bodies, and raw peer close reasons must not be logged.

## Request lifecycle

1. Minecraft opens the WebSocket and sends exactly one `hello`.
2. pi replies with `status: ready` after validating `hello`.
3. Minecraft sends a `message` with a new request UUID.
4. pi emits zero or more ordered `chunk` messages for that request.
5. pi emits exactly one terminal `complete` or request-scoped `error`.

A request ID must not be reused. Valid chunk sequences begin at zero and increase by exactly one. `complete.sequence` is the number of chunks sent, so it must equal the next expected sequence.

The companion extension accepts only one Minecraft-owned pi turn at a time because current pi events do not attach external correlation metadata. It first verifies pi's `input` event has source `extension`, then verifies the following user-message event matches the submitted Minecraft prompt, and requires that acceptance sequence within 10 seconds. A concurrent Minecraft request receives a retryable `busy` error. If another user message enters the active pi session, the extension emits `session_interleaved`, immediately releases request ownership, and stops associating output with the Minecraft request. This is preferable to mixing output under an incorrect request ID.

The mod keeps independent state per request ID, checks every sequence, and routes output only to the requesting player UUID. Unknown, expired, duplicated, missing, or out-of-order response data is not assigned to another request.

Neither side automatically replays prompts after a timeout or disconnect: an agent may already have executed tools or modified files.

## Minecraft → pi messages

### `hello`

Must be the first application message on a connection.

```json
{
  "version": 1,
  "type": "hello",
  "client": "http-request-mod",
  "server": "Minecraft Server"
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `client` | string | Exactly `http-request-mod`. |
| `server` | string | Informational Minecraft server name, at most 256 UTF-16 code units. It must not be trusted or logged as code. |

The extension requires `hello` within five seconds and closes with code 1002 otherwise.

### `message`

Submits one player-selected prompt.

```json
{
  "version": 1,
  "type": "message",
  "requestId": "4ec90913-ec0c-4a42-b65a-f67fb3b23547",
  "player": {
    "id": "c8a90d67-d9c4-4fd2-8e27-358f054d3373",
    "name": "PlayerName"
  },
  "content": "Inspect the failing test"
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `requestId` | UUID string | Unique correlation ID generated by the mod. |
| `player.id` | UUID string | Informational submitting player ID. The extension does not use it for authorization. |
| `player.name` | string | Informational submitting name, 1–64 UTF-16 code units. |
| `content` | string | Nonblank prompt, at most 4,096 Unicode code points. |

The extension forwards `content` followed by a random HTML-comment correlation marker to `pi.sendUserMessage`. The marker is generated inside the extension, is not returned over the wire, and lets it distinguish this turn from same-text interactive or third-party-extension prompts. Player metadata is never injected into agent context.

## pi → Minecraft messages

### `status`

Reports connection or active-session state. It is not terminal for a request.

```json
{
  "version": 1,
  "type": "status",
  "status": "ready",
  "message": "Connected to the active pi session"
}
```

`status` is at most 64 UTF-16 code units. Optional `message` is at most 1,024. The mod sanitizes these values and renders them as literal text to authorized dedicated-server operators or the integrated-server owner.

Defined status values are:

- `ready` — the extension accepted `hello` and the connection can submit a prompt when the session is idle.
- `closing` — the pi session is shutting down, switching, forking, or reloading.

Future values may be added; clients should display unknown values safely.

### `chunk`

Carries incremental assistant-visible text. Thinking and tool arguments are never relayed.

```json
{
  "version": 1,
  "type": "chunk",
  "requestId": "4ec90913-ec0c-4a42-b65a-f67fb3b23547",
  "sequence": 0,
  "content": "I found "
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `requestId` | UUID string | ID from `message`. |
| `sequence` | nonnegative integer | Exact zero-based chunk order. |
| `content` | string | Incremental assistant text. The reference extension limits each chunk to 4,096 Unicode code points and the overall frame limit still applies. |

### `complete`

Terminal successful completion.

```json
{
  "version": 1,
  "type": "complete",
  "requestId": "4ec90913-ec0c-4a42-b65a-f67fb3b23547",
  "sequence": 17
}
```

`sequence` equals the number of chunks emitted. A response with chunks `0` through `16` therefore completes with `sequence: 17`.

### `error`

Reports a protocol, session, connection, or request failure.

```json
{
  "version": 1,
  "type": "error",
  "requestId": "4ec90913-ec0c-4a42-b65a-f67fb3b23547",
  "code": "busy",
  "message": "The pi session is currently busy",
  "retryable": true
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `requestId` | optional UUID string | Present for a request-scoped terminal error. Omitted for connection/session/protocol errors. |
| `code` | string | Stable machine-readable code, at most 64 UTF-16 code units. |
| `message` | string | Credential-safe display text, at most 1,024 UTF-16 code units. |
| `retryable` | boolean | Whether retrying as a **new request ID** may succeed. Defaults to false when omitted. |

Reference error codes:

| Code | Scope | Meaning |
| --- | --- | --- |
| `invalid_message` | protocol/request | JSON shape, ordering, or required field is invalid. |
| `unsupported_version` | protocol | `version` is not 1. |
| `prompt_too_large` | request | Prompt exceeds 4,096 code points. |
| `response_too_large` | request | Response exceeds 262,144 UTF-16 code units; earlier chunks remain valid. |
| `duplicate_request` | request | The request UUID was already used. |
| `busy` | request | pi or another Minecraft request is active. |
| `session_unavailable` | request/session | The session cannot accept or finish the request. |
| `session_interleaved` | request | Another user prompt entered pi, so correlation is no longer safe. |
| `timeout` | request | The extension's total request deadline expired. |
| `agent_error` | request | The final assistant run ended in error or was aborted. |
| `internal_error` | session | The extension could not safely encode or deliver a result. |

Peers must display only sanitized messages, never raw exception text or raw malformed payloads.

## Limits, timeout, and display behavior

| Limit | Reference value |
| --- | --- |
| WebSocket application frame | 65,536 UTF-8 bytes |
| Prompt | 4,096 Unicode code points |
| Extension response chunk | 4,096 Unicode code points |
| Extension total response per request | 262,144 UTF-16 code units |
| Mod total response per request | 262,144 UTF-16 code units |
| Concurrent pending requests in mod | 8 |
| Concurrent Minecraft-owned requests in extension | 1 |
| Prompt acceptance timeout in extension | 10 seconds |
| Default total request timeout | 120 seconds, configurable 10–1800 |
| Minecraft response text per component | 240 Unicode code points plus a short correlation prefix |
| Minecraft components per request | 1,024; later text gets a visible omission warning |
| Minecraft component delivery rate | at most 4 per second |

The mod strips control characters other than newline and tab, uses only `Text.literal`, coalesces token-sized chunks for up to four server ticks, splits at newlines and Unicode code-point boundaries, and retains already queued output if a later limit or protocol error occurs. All game state and UI access runs on the Minecraft main server thread.

## Reconnect and close behavior

After an unexpected transport close or failed connection, the mod retries after 1, 2, 4, 8, 16, and then 30 seconds; later delays remain bounded at 30 seconds. Invalid endpoint policy is not retried. Manual disconnect and server shutdown suppress reconnects.

Reference close codes:

| Code | Meaning |
| --- | --- |
| 1000 | Normal manual disconnect or Minecraft server stop. |
| 1002 | Missing/invalid initial hello or protocol ordering. |
| 1003 | Binary data is unsupported. |
| 1009 | `ws` rejected a payload above its configured maximum. |
| 1011 | Outgoing backpressure or send failure. |
| 1012 | pi session shutdown/reload/replacement; the mod may reconnect. |

Malformed application JSON normally receives an `error` without closing the connection. Oversized transport data and invalid WebSocket framing are handled by the WebSocket implementations.
